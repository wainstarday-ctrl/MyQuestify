# Мобильная сборка (Android)

Раздел описывает, как собрать приложение для телефона и почему оно устроено
именно так.

---

## Устройство сборки

Настольная версия состоит из двух частей: интерфейса на HTML и JavaScript и
сервера на Python. Интерфейс переносится без изменений — это обычная
веб-страница. Сервер на телефон не переносится.

Вместо него подключается `static/js/local-api.js` — реализация тех же
адресов и тех же форм ответов средствами браузера. Подмена происходит в
одной функции `api.request`, поэтому весь остальной код приложения о режиме
не знает.

```
Настольная версия          Мобильная версия
┌──────────────┐           ┌──────────────┐
│  Интерфейс   │           │  Интерфейс   │  ← один и тот же
└──────┬───────┘           └──────┬───────┘
       │ HTTP                     │ вызов функции
┌──────▼───────┐           ┌──────▼───────┐
│ FastAPI      │           │ local-api.js │
│ SQLAlchemy   │           │              │
│ SQLite-файл  │           │ IndexedDB    │
└──────────────┘           └──────────────┘
```

### Почему не перенесли Python

Существуют способы запустить Python на Android — Chaquopy, BeeWare. Оба
добавляют к приложению исполняющую среду языка: файл вырастает с нескольких
мегабайт до пятидесяти и более, запуск занимает секунды, а расход памяти
растёт настолько, что на устройстве с двумя гигабайтами приложение
вытесняется системой при первом же переключении.

Переписать серверную логику оказалось дешевле: содержательной части в ней
около восьмисот строк, остальное — описания и проверки типов, которых в
браузере не требуется.

## Что отличается от настольной версии

| Возможность | Настольная | Мобильная | Почему |
|---|---|---|---|
| Квесты, экономика, приоритеты | да | да | перенесены полностью |
| Цепочки мыслей и паутина | да | да | |
| Девять интерактивных сцен | да | да | с упрощением на слабых устройствах |
| Календарь и статистика | да | да | |
| Два языка | да | да | |
| Языковая модель | да | **нет** | см. ниже |
| Разбор квеста моделью | да | по шаблону | без модели |
| Напоминания при закрытом приложении | трей | системные уведомления | разные механизмы |
| Поворот предмета в сцене | клавиши Q и E | экранные кнопки | на телефоне нет клавиатуры |

### О языковой модели

Настольные выпуски существуют в двух разновидностях — с моделью и без неё.
Для Android такой разновидности нет, и причин тому две.

**Память.** Модель на полтора миллиарда параметров требует около 1360 МБ:
1060 под веса, 180 под контекст, ещё 120 под исполняющую среду. Android
отдаёт одному приложению примерно 45 % оперативной памяти — остальное
занимают система и прочие приложения. На устройстве с двумя гигабайтами
это около 920 МБ, чего заведомо мало. Приложение было бы закрыто системой
раньше, чем модель успела бы ответить.

| Память устройства | Доступно приложению | Достаточно |
|---|---|---|
| 2 ГБ | ~920 МБ | нет |
| 3 ГБ | ~1380 МБ | впритык |
| 4 ГБ | ~1840 МБ | да |

Требование «работать на слабых устройствах» и наличие модели несовместимы:
пришлось бы выбрать одно.

**Отсутствие средства выполнения.** Мобильная сборка не содержит Python —
серверная логика переписана на JavaScript. Выполнить модель в ней нечем:
llama.cpp пришлось бы собирать под ARM и подключать отдельным дополнением
к оболочке, а из JavaScript вызывать через мост. Это не подключение
готового файла, а самостоятельная задача сравнимого с проектом объёма.

Вместо генерации используется набор заготовленных фраз — тот же механизм,
что и в настольной версии при отсутствии весов. Фраз здесь вдвое больше,
поскольку они не запасной путь, а единственный.

Возможный путь на будущее — модель существенно меньшего размера
(полмиллиарда параметров, около 350 МБ) через сборку llama.cpp для
WebAssembly. Качество ответов при этом заметно ниже, а на слабых
устройствах задача всё равно остаётся нерешённой.

## Как устроены напоминания

Настольная версия просматривает базу раз в минуту и показывает сообщение
сама. На телефоне так нельзя: приложение засыпает сразу после свёртывания,
и никакой его код в это время не выполняется.

Поэтому подход обратный. Приложение заранее передаёт системе список
моментов, в которые нужно показать сообщение, а дальше их доставляет
операционная система — надёжнее любого фонового процесса и без расхода
заряда.

Следствие: расписание перепланируется при каждом изменении списка квестов.
Отданное системе расписание от приложения уже не зависит и само не
обновится, поэтому создание, завершение, правка и удаление квеста заново
пересчитывают весь набор.

Разрешение на показ сообщений спрашивается при включении напоминаний в
настройках, а не при первом запуске: запрос без понятной причины
пользователи отклоняют, а вернуть его потом можно только через настройки
устройства.

## Управление без клавиатуры

Лаборатория Идей наклоняет колбу клавишами поворота. На сенсорном
устройстве вместо них появляются две круглые кнопки в углу сцены.

Кнопки подают сцене те же события, что и настоящая клавиатура, поэтому сами
сцены о них не знают и не содержат ветвлений под сенсорный ввод. Коды клавиш
берутся из настроек: переназначение на настольной машине отражается и на
экранных кнопках.

Размер кнопки — 56 точек. Это принятый минимум для надёжного попадания
пальцем; при меньшем растёт доля промахов, а промах в сцене означает
случайное действие вместо задуманного.

## Согласование с оболочкой

Три особенности телефона, без учёта которых приложение ощущается чужеродным.

**Аппаратная кнопка «назад».** По умолчанию закрывает приложение. Обработчик
закрывает то, что открыто, в порядке вложенности: сначала окно, затем
предпросмотр сцены, затем возврат из беседы к сцене. Если закрывать нечего,
приложение **сворачивается, а не завершается** — напоминания о сроках
работают, пока оно не закрыто окончательно.

**Строка состояния.** Её цвет задаёт приложение, и он меняется вместе с
темой. Иначе на светлой теме светлые значки становятся невидимыми.

**Возврат из фона.** Android выгружает приложение из памяти, но страница
сохраняется, и данные на ней устаревают. При возвращении после минуты
отсутствия состояние перечитывается: сроки за это время могли пройти.
Короткое переключение между приложениями перечитывания не вызывает — за
несколько секунд ничего не меняется, а лишний запрос заметен паузой.

**Заставка.** Оболочка показывает свою заставку до готовности страницы, а
приложение — свою, с цитатой. Первая скрывается в момент появления второй:
скрытие по готовности приложения давало бы белую вспышку между ними.

## Профили производительности

Ядро сцен определяет возможности устройства при запуске и выбирает один из
трёх режимов. Выбранный профиль выводится в журнал браузера.

| Профиль | Когда | Частиц | Плотность точек | Свечение |
|---|---|---|---|---|
| `high` | настольные машины | все | до 2.5× | полное |
| `medium` | телефоны от 4 ГБ | 55 % | до 1.5× | полное |
| `low` | 2 ГБ или 4 ядра с сенсорным вводом | 28 % | 1× | упрощённое |

Свечение отключается первым: радиальный градиент поверх кадра в режиме
сложения — самая дорогая операция отрисовки, и именно она первой роняет
частоту кадров.

## Сборка

Потребуются Node.js и Android Studio.

### Один раз

```powershell
# 1. Значки приложения
python tools/make_android_icons.py

# 2. Зависимости и каркас проекта Android
cd mobile
npm install
npm run build
npx cap add android
```

### 3. Значки в проект

Скопировать содержимое `mobile/android-icons` в
`mobile/android/app/src/main/res`, заменяя существующие папки `mipmap-*`.

Затем создать файл
`mobile/android/app/src/main/res/mipmap-anydpi-v26/ic_launcher.xml`:

```xml
<?xml version="1.0" encoding="utf-8"?>
<adaptive-icon xmlns:android="http://schemas.android.com/apk/res/android">
    <background android:drawable="@mipmap/ic_launcher_background" />
    <foreground android:drawable="@mipmap/ic_launcher_foreground" />
</adaptive-icon>
```

Такой же файл под именем `ic_launcher_round.xml` с тем же содержимым.

Эти два файла говорят системе, что значок состоит из двух слоёв, и она сама
обрежет его под форму, принятую на устройстве: круг, квадрат со скруглением
или каплю. Без них на устройствах от восьмой версии Android значок окажется
вписанным в белый квадрат.

### При каждом изменении

```powershell
cd mobile
npm run sync           # пересобирает www и переносит в проект Android
npx cap open android   # откроется Android Studio
```

Дальше сборка идёт средствами Android Studio: `Build → Build Bundle(s) / APK(s) → Build APK(s)`.

Готовый файл появится в
`mobile/android/app/build/outputs/apk/debug/app-debug.apk`.

### Установка на телефон

Скопировать файл на устройство и открыть его. Android спросит разрешение на
установку из неизвестного источника — это обычное поведение для приложений,
собранных не из магазина.

Для проверки по кабелю в Android Studio есть кнопка `Run`: приложение
установится и запустится само, а сообщения об ошибках будут видны в панели
`Logcat`.

## Проверка без телефона

Мобильный режим работает и в обычном браузере: достаточно открыть
`mobile/www/index.html` через любой локальный веб-сервер.

```bash
cd mobile/www
python -m http.server 8000
```

Затем открыть `http://127.0.0.1:8000` и в инструментах разработчика включить
режим устройства. Через файловый адрес открывать нельзя: браузер запрещает
таким страницам обращаться к хранилищу.

## Выпуск для публикации

Сборка через `Build → Build APK(s)` даёт отладочный файл: он подписан
временным ключом, действует ограниченное время и не годится для раздачи.
Для выпуска нужен собственный ключ подписи.

### 1. Создать ключ (один раз)

```powershell
cd mobile\android\app
keytool -genkey -v -keystore myquestify.keystore -alias myquestify `
    -keyalg RSA -keysize 2048 -validity 10000
```

Программа спросит пароль и несколько сведений о владельце. Пароль
понадобится при каждой сборке.

**Файл ключа и пароль нельзя терять.** Обновление приложения принимается
Android только при совпадении подписи: с другим ключом это будет считаться
другим приложением, и установить его поверх прежнего не удастся.

Ключ не попадает в репозиторий — он исключён в `.gitignore`.

### 2. Указать ключ сборке

Создать файл `mobile/android/keystore.properties`:

```properties
storeFile=myquestify.keystore
storePassword=ваш_пароль
keyAlias=myquestify
keyPassword=ваш_пароль
```

Затем в `mobile/android/app/build.gradle` внутри блока `android { }`
добавить:

```gradle
def keystoreProperties = new Properties()
def keystorePropertiesFile = rootProject.file('keystore.properties')
if (keystorePropertiesFile.exists()) {
    keystoreProperties.load(new FileInputStream(keystorePropertiesFile))
}

signingConfigs {
    release {
        storeFile file(keystoreProperties['storeFile'])
        storePassword keystoreProperties['storePassword']
        keyAlias keystoreProperties['keyAlias']
        keyPassword keystoreProperties['keyPassword']
    }
}

buildTypes {
    release {
        signingConfig signingConfigs.release
        minifyEnabled false
        shrinkResources false
    }
}
```

Сжатие кода отключено намеренно: приложение и без него занимает несколько
мегабайт, а инструмент сжатия способен удалить обращения, которые находит
только во время выполнения — например, вызовы плагинов Capacitor.

### 3. Собрать

```powershell
cd mobile
npm run sync
cd android
.\gradlew assembleRelease
```

Готовый файл:
`mobile/android/app/build/outputs/apk/release/app-release.apk`

Переименовать перед публикацией, например в
`MyQuestify-1.6.0-android.apk`.

### Универсальность файла

Собранный таким образом файл содержит код под все поддерживаемые
разновидности процессоров и устанавливается на любое устройство с Android
шестой версии и выше. Разделение по разновидностям процессора сократило бы
размер, но потребовало бы от пользователя выбирать нужный файл — при объёме
в несколько мегабайт выигрыш того не стоит.

Проверить перечень:

```powershell
cd mobile\android
.\gradlew :app:dependencies --configuration releaseRuntimeClasspath
```

## Что проверить перед публикацией

Приложение стоит открыть на устройстве и убедиться в следующем.

| Проверка | На что смотреть |
|---|---|
| Первый запуск | появляется экран загрузки с цитатой, затем интерфейс |
| Создание квеста | календарь открывается и помещается на экран |
| Сцена | занимает большую часть высоты, отзывается на касание |
| Лаборатория | в углу видны две кнопки поворота, колба наклоняется |
| Уведомления | при включении система спрашивает разрешение |
| Поворот устройства | сцена перестраивается, интерфейс не ломается |
| Возврат в приложение | после свёртывания данные на месте |

Отдельно стоит проверить на устройстве постарше: профиль отрисовки
выбирается по числу ядер и объёму памяти, и на слабом устройстве должен
включиться упрощённый режим. Выбранный профиль виден в журнале, который
открывается в Android Studio на панели `Logcat`.
