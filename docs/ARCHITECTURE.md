# Архитектура и проектные решения

Документ описывает устройство приложения и обоснование принятых решений.
Каждый раздел отвечает на вопрос «почему сделано именно так», а не только
«как устроено»: альтернативы рассматривались, и отказ от них имеет причины.

---

## 1. Общая схема

```
┌─────────────────────────────────────────────────┐
│  Окно PyWebView (Microsoft Edge WebView2)       │
│  ┌───────────────────────────────────────────┐  │
│  │  Веб-интерфейс: HTML + CSS + Vanilla JS   │  │
│  │  Matter.js — физика интерактивных сцен    │  │
│  └───────────────────┬───────────────────────┘  │
└──────────────────────┼──────────────────────────┘
                       │ HTTP, только 127.0.0.1
┌──────────────────────┼──────────────────────────┐
│  Процесс приложения  ▼                          │
│  ┌───────────────────────────────────────────┐  │
│  │  FastAPI + uvicorn (фоновый поток)        │  │
│  ├───────────────────────────────────────────┤  │
│  │  SQLAlchemy → aiosqlite → SQLite (файл)   │  │
│  ├───────────────────────────────────────────┤  │
│  │  llama-cpp-python → GGUF-модель (ЦП)      │  │
│  ├───────────────────────────────────────────┤  │
│  │  Планировщик напоминаний → значок в трее  │  │
│  └───────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

Приложение представляет собой единый процесс: графическая оболочка и
веб-сервер работают внутри него, обмениваясь данными по локальному HTTP.

### Почему клиент-серверная схема внутри одного процесса

Альтернатива — вызывать функции Python напрямую из JavaScript через мост
PyWebView. От неё отказались по трём причинам:

1. **Переносимость.** Интерфейс остаётся обычной веб-страницей, не знающей
   о PyWebView. При переносе на Android достаточно заменить оболочку,
   не трогая ни разметку, ни прикладную логику.
2. **Отладка.** API доступен по адресу `127.0.0.1:8731` из любого браузера,
   а интерактивная документация FastAPI (`/docs`) позволяет проверять
   обработчики без интерфейса.
3. **Разделение слоёв.** Бизнес-логика не смешивается с кодом отображения,
   что упрощает изменения в каждом из слоёв по отдельности.

Плата за это — накладные расходы на сериализацию JSON, пренебрежимо малые
при десятках запросов за сеанс.

## 2. Выбор технологий

| Слой | Решение | Отвергнутая альтернатива и причина |
|---|---|---|
| Веб-фреймворк | FastAPI | Flask — нет встроенной валидации и асинхронности; генерация ответа моделью блокировала бы сервер |
| Оболочка | PyWebView | Electron — около 150 МБ собственной сборки браузера в дистрибутиве; Tkinter — невозможно реализовать заданное оформление |
| СУБД | SQLite | PostgreSQL — требует установки сервера пользователем, что противоречит формату настольного приложения |
| Доступ к данным | SQLAlchemy | Прямые запросы через `sqlite3` — схема размывается по коду, выше риск ошибок и инъекций |
| Физика | Matter.js | Box2D для веба — требует WebAssembly, объём больше без выигрыша в возможностях |
| Интерфейс | Vanilla JS | React — сборщик и `node_modules` ради одного окна с состоянием в один объект |
| Инференс | llama-cpp-python | transformers — полноразмерные веса и расчёт на видеокарту |
| Сборка | PyInstaller | cx_Freeze — хуже поддержка нативных библиотек llama.cpp |

## 3. Ключевые решения по данным

### Разделение ресурсов и данных

`app/config.py` различает два корневых каталога:

* `RESOURCE_DIR` — только чтение: разметка, стили, скрипты, иконка;
* `DATA_DIR` — чтение и запись: база, журнал, загруженные фоны, модель.

Причина: PyInstaller в режиме одного файла распаковывает ресурсы во
временный каталог, доступный только на чтение и удаляемый при выходе.
Без разделения база создавалась бы там же и исчезала после закрытия
приложения. В собранной версии `DATA_DIR` указывает на
`%LOCALAPPDATA%\MyQuestify` — единственное место, куда приложение может
писать без прав администратора.

### Хранение времени

SQLite не хранит смещение часового пояса: диалект записывает компоненты
даты и возвращает объект без указания зоны, даже если колонка объявлена с
`timezone=True`. Функция `ensure_utc` в `app/models.py` трактует такое
значение как UTC — именно в UTC оно записывалось — и приводит его к виду с
явной зоной перед отправкой клиенту.

Без этого шага Pydantic сериализовал бы время без суффикса `Z`, а
`new Date()` в браузере прочитал бы строку как местное время. Дедлайн
смещался бы ровно на часовой пояс пользователя.

### Награда хранится в записи задачи

Поле `reward` заполняется при создании квеста, а не вычисляется при выдаче.
Изменение тарифа в конфигурации не должно переоценивать задним числом уже
созданные квесты: пользователь принимал их, рассчитывая на объявленную
награду. По той же причине отдельно хранится `penalty`.

### Уровень сцены пересчитывается от факта

`_recalculate_tree_level` считает уровень как функцию от числа завершённых
квестов, а не увеличивает счётчик при каждом завершении. Инкремент
разошёлся бы с действительностью при любой правке данных; расчёт от факта
воспроизводим и самовосстанавливается.

### Облегчённые миграции

`create_all` создаёт только отсутствующие таблицы и не изменяет
существующие. У пользователя, обновившего приложение, новые колонки не
появились бы, и запрос завершался бы ошибкой. Функция `_apply_migrations`
проверяет состав колонок через `PRAGMA table_info` и добавляет недостающие
через `ALTER TABLE`.

Полноценная система миграций (Alembic) для одного файла SQLite и
однопользовательского приложения избыточна: она добавила бы каталог версий
и зависимость ради операций, умещающихся в список из четырёх строк.

## 4. Работа с языковой моделью

### Ленивая загрузка

Веса читаются при первом обращении, а не при старте. Загрузка модели на
1.5 млрд параметров занимает десятки секунд; при загрузке на старте окно
открывалось бы всё это время пустым.

### Сериализация доступа

Экземпляр `Llama` не является потокобезопасным, поэтому обращения к нему
выстраиваются в очередь через `asyncio.Lock`. Одновременный вызов из двух
обработчиков привёл бы к повреждению внутреннего состояния.

### Вынос в пул потоков

Инференс — вычислительная операция, полностью занимающая поток. Без
`run_in_threadpool` цикл событий останавливался бы на время генерации, и
интерфейс переставал бы отвечать.

### Отказоустойчивость

Функция `_generate` не выбрасывает исключений: отсутствие пакета,
отсутствие файла модели, повреждённые веса и ошибка инференса приводят к
выдаче резервной фразы. Создание квеста не должно срываться из-за
необязательного компонента.

### Независимость от конкретной модели

`app/prompt_formats.py` содержит пять шаблонов разметки диалога и
определяет нужный по метаданным GGUF, а при их отсутствии — по имени
файла. Промпт в чужом формате модель воспринимает как обычный текст и
отвечает мимо инструкции, поэтому автоматическое определение —
не удобство, а условие работоспособности при смене модели.

## 5. Безопасность диалога с Оракулом

Проверка выполняется **до** обращения к модели, детерминированным кодом в
`app/oracle_safety.py`.

Обоснование: модель на 1.5 млрд параметров следует системному промпту
нестабильно и нарушает запрет при настойчивой формулировке. Инструкция в
промпте — это просьба, которую можно переформулировать; регулярное
выражение переформулировать нельзя.

Три исхода:

* `CRISIS` — признаки мыслей о самоповреждении. Художественный образ
  Оракула снимается: иносказательная речь в такой момент воспринимается
  как отстранённость. Ответ прямой, с предложением обратиться к человеку.
* `HARMFUL` — просьба, ведущая к вреду или нарушению закона. Отказ и
  перевод разговора к причине обращения.
* `ALLOW` — обычный разговор, передаётся модели.

Сгенерированный ответ проверяется повторно: модель может перейти к опасной
теме самостоятельно, даже если вопрос был безобидным.

Списки выражений намеренно широкие. Ложное срабатывание стоит одного
неуместного ответа, пропуск — существенно дороже.

## 6. Интерактивные сцены

### Разделение динамики и отрисовки

Штатный `Matter.Render` предназначен для отладки и заливает тела сплошным
цветом. Ядро `stage.js` использует Matter только для расчёта динамики, а
кадр рисует самостоятельно: радиальные градиенты со смещённым центром,
контактные тени, свечение в режиме сложения, масштабирование под
плотность экрана.

### Собственное перетаскивание

`MouseConstraint` из состава Matter захватывает любое тело под курсором,
включая статичную декорацию, и поглощает нажатие. В результате клики по
сцене не доходили до обработчика. Ядро сначала ищет тело среди
объявленных сценой перетаскиваемых, с допуском 26 пикселей — мелкие
объекты иначе почти невозможно захватить, — и лишь затем передаёт нажатие
сцене.

### Сцены без физического движка

Три сцены — «Механизм Времени», «Орбиты Замысла», «Плетение Смыслов» и
«Лаборатория Идей» — считают динамику самостоятельно (`usesPhysics: false`).
Зацепление шестерён, движение по орбите, упругая сеть и объём жидкости
описываются несколькими строками математики; через тела и связи движка
пришлось бы бороться с проскальзыванием и накоплением ошибки.

### Три модели в одной сцене

«Лагерь Уединения» совмещает три независимые модели, и это разделение
вынужденное, а не декоративное.

* **Поленья** — тела Matter с обычной гравитацией: их бросают, они
  сталкиваются и складываются в кучу.
* **Пламя и искры** считаются отдельно, потому что для них гравитация
  обратная — нагретый воздух несёт частицы вверх, — а движок работает с
  единым для всего мира вектором силы тяжести.
* **Котелок** подвешен на связи Matter: маятник достоверно передаётся
  именно связью, тогда как ручной расчёт потребовал бы отдельного
  интегратора ради одного предмета.

Связующее звено — топливо. Каждое полено несёт запас, который расходуется,
только пока полено лежит в очаге; отброшенное в сторону огонь не
поддерживает. От суммарного запаса зависят высота пламени, плотность потока
искр и освещённость палатки, камней и земли.

Скорость горения подобрана так, чтобы полено прогорало примерно за три
минуты. Более быстрое горение превращало бы сцену в бесконечное
подбрасывание дров, более медленное сделало бы запас незаметным — и вся
модель потеряла бы смысл. Раздувание ускоряет расход в три с половиной
раза: пламя вырастает сразу, но запас тратится быстрее, поэтому раздувание
остаётся выбором, а не бесплатным улучшением.

Полностью потухнуть костёр не может: нижняя граница интенсивности оставляет
тлеющие угли. Иначе сцена превратилась бы в чёрный прямоугольник, из
которого нет выхода без нового полена.

### Защита цикла кадров

Необработанное исключение внутри `requestAnimationFrame` останавливает
цикл навсегда и без диагностики: сцена замирает чёрным прямоугольником.
Кадр обёрнут в перехват; после серии ошибок цикл останавливается явно, с
сообщением на холсте.

## 7. Особенности платформы Windows

| Решение | Причина |
|---|---|
| `multiprocessing.freeze_support()` | без него собранный файл при создании дочернего процесса запускает собственную копию |
| `SetProcessDpiAwareness` | при масштабировании экрана 125–150 % изображение растягивается системой и теряет резкость |
| Именованный мьютекс | две копии писали бы в одну базу и открыли бы два окна |
| `gui='edgechromium'` | автоматический выбор может подставить устаревший компонент без поддержки `backdrop-filter` |
| Проверка WebView2 Runtime | при отсутствии компонента окно открывается пустым без какой-либо ошибки |
| `MessageBoxW` для ошибок | в оконном режиме сборки консоли нет, вывод в поток недоступен |
| Журнал в файл | `sys.stderr` равен `None`; стандартная настройка логирования завершилась бы ошибкой при первой записи |
| `DB_PATH.as_posix()` | обратная косая черта нарушает разбор URL соединения в SQLAlchemy |
| UPX отключён | сжатие повреждает нативные библиотеки llama.cpp и вызывает ложные срабатывания антивирусов |

### Отказ от диалогов браузера

`window.prompt`, `window.confirm` и `window.alert` блокируются компонентом
WebView2: вызов возвращает отказ без каких-либо признаков ошибки, и
действие не выполняется. Во всём интерфейсе они не используются: ввод
выполняется полем в строке элемента, а необратимые действия
подтверждаются повторным нажатием той же кнопки.

## 8. Оформление интерфейса

### Liquid Glass из четырёх слоёв

1. **Источник цвета** — размытые цветные пятна под панелями. Без цвета
   позади размытие даёт равномерно-серый результат.
2. **Заливка с `backdrop-filter: blur() saturate(180%)`** — насыщение
   возвращает цвет, который съедает размытие.
3. **Светящаяся кромка** через `mask-composite` — градиент обрезается до
   полосы в один пиксель, поэтому свет по периметру неравномерен.
4. **Внутренние тени** сверху и снизу — задают толщину стекла.

### Светлая тема как отдельный набор значений

Светлое оформление не является инверсией тёмного. Белое стекло на белом
фоне исчезает, поэтому на светлой теме заливка панели плотнее фона, кромка
тоньше, а отрыв от подложки обеспечивают внешние тени вместо внутренней
подсветки. Акценты приглушены: значения, читаемые на тёмном, на светлом
дают избыточный контраст.

### Часовая шкала на карточке квеста

Одно деление соответствует одному часу и, следовательно, десяти токенам.
Шкала отображает величину, из которой вычисляется награда, а не абстрактный
прогресс.

## 9. Ограничения реализации

Раздел приводится для полноты: перечисленное — осознанные границы, а не
недоработки.

1. **Напоминания работают, пока запущен процесс.** Закрытие окна сворачивает
   приложение в область уведомлений, но после перезагрузки компьютера
   напоминания не придут. Независимая доставка требует регистрации задачи
   в планировщике заданий операционной системы, то есть установки.
2. **Приложение однопользовательское.** Идентификатор пользователя
   зафиксирован константой. Многопользовательский режим потребовал бы
   аутентификации, что противоречит формату локального приложения.
3. **Сцены отображаются в тёмном оформлении в обеих темах.** Они рисуются
   собственными градиентами; светлый вариант потребовал бы второго набора
   палитр для девяти сцен.
4. **Качество ответов ограничено размером модели.** Модель на 1.5 млрд
   параметров допускает фактические ошибки. Это компенсируется характером
   применения — короткие мотивирующие фразы — и правовой оговоркой.
