# Локальная языковая модель

Приложение поставляется **без весов**. Модель подключается пользователем и
работает офлайн: сетевых обращений при генерации нет.

Без модели приложение полностью работоспособно — вместо генерации
используется детерминированный набор фраз, а статус виден в шапке
интерфейса.

---

## Модель проекта

Разработка и проверка велись на **Vikhr-Qwen-2.5-1.5B-Instruct**,
квантование **Q4_K_M** (~1.1 ГБ).

| | |
|---|---|
| Страница модели | <https://huggingface.co/Vikhrmodels/Vikhr-Qwen-2.5-1.5B-Instruct-GGUF> |
| Файл | `Vikhr-Qwen-2.5-1.5b-Instruct-Q4_K_M.gguf` |
| Базовая модель | Qwen2.5-1.5B-Instruct |
| Формат промпта | ChatML |
| Рекомендуемая температура | ≈ 0.3 |

Выбор обоснован тремя требованиями проекта:

1. **Русский язык.** Модель дообучена на русскоязычном корпусе, тогда как
   базовый Qwen2.5 отвечает по-русски заметно хуже.
2. **CPU-инференс.** Полтора миллиарда параметров в 4-битном квантовании
   дают ответ за секунды на обычном процессоре без видеокарты.
3. **Размер.** ~1.1 ГБ помещается на флеш-накопитель вместе с приложением.

Параметр температуры задан в `app/config.py`:

```python
LLM_TEMPERATURE: Final[float] = 0.3
```

На значениях выше 0.6 модель такого размера начинает терять связность.

## Куда положить файл

Файл должен называться `model.gguf`.

| Режим запуска | Путь |
|---|---|
| `python run.py` | `<корень проекта>\models\model.gguf` |
| `MyQuestify.exe` | `%LOCALAPPDATA%\MyQuestify\models\model.gguf` |

Каталог создаётся при первом запуске. Внутри `.exe` этого каталога нет:
PyInstaller распаковывает ресурсы во временную папку, доступную только на
чтение и стираемую при выходе.

## Подключение другой модели

Приложение работает с любым файлом в формате **GGUF**, который открывает
`llama-cpp-python`. Достаточно переименовать файл в `model.gguf` и
перезапустить приложение.

### Поддерживаемые форматы промпта

Инструктивные модели обучались на разметке диалога, и каждое семейство
размечает его по-своему. Промпт в чужом формате модель воспринимает как
обычный текст: она отвечает мимо инструкции, дописывает реплики за
пользователя или зацикливается.

| Формат | Семейства | Разметка |
|---|---|---|
| `chatml` | Qwen, Vikhr, Yi, OpenChat, Hermes | `<\|im_start\|>role` |
| `llama3` | Llama 3 / 3.1 / 3.2, Saiga-Llama3 | `<\|start_header_id\|>` |
| `mistral` | Mistral, Mixtral, Zephyr | `[INST] … [/INST]` |
| `gemma` | Gemma, Gemma 2 | `<start_of_turn>` |
| `alpaca` | Vicuna, WizardLM и прочие текстовые | `### Инструкция:` |

### Автоопределение

Формат подбирается сам, в таком порядке:

1. **Явная настройка** `LLM_PROMPT_FORMAT` в `app/config.py`.
2. **Метаданные GGUF** — поле `tokenizer.chat_template` внутри файла.
   Надёжнее имени: файл легко переименовать, а шаблон остаётся от обучения.
3. **Имя файла** — по характерным словам (`qwen`, `llama-3`, `mistral`…).
4. **ChatML** как запасной вариант.

Выбранный формат пишется в журнал при загрузке модели:

```
LLM загружена: model.gguf (потоков: 8, формат: ChatML (Qwen, Vikhr, Yi, OpenChat))
```

### Если ответы бессвязны

Скорее всего, формат определён неверно. Задайте его вручную в
`app/config.py`:

```python
LLM_PROMPT_FORMAT: Final[str] = "llama3"   # вместо "auto"
```

Прочие признаки и что они означают:

| Симптом | Причина | Что делать |
|---|---|---|
| Модель дописывает реплики за пользователя | неверный формат | задать вручную |
| Ответы обрываются на полуслове | мал `LLM_MAX_TOKENS` | увеличить в конфиге |
| Ответ на английском | модель без русского корпуса | взять модель с поддержкой русского |
| Бессвязный текст, повторы | высокая температура | снизить `LLM_TEMPERATURE` |
| Долгий первый ответ | модель грузится с диска | это разовая задержка на сеанс |
| Ответ дольше 30 секунд | модель слишком велика для этого ЦП | взять модель меньше или квантование сильнее |

## Требования к оборудованию

| Размер модели | Оперативная память | Время ответа на 4 ядрах |
|---|---|---|
| 0.5 млрд, Q4 | ~1 ГБ | 1–2 с |
| 1.5 млрд, Q4 | ~2 ГБ | 3–6 с |
| 7–8 млрд, Q4 | ~6 ГБ | 20–60 с |

Инференс идёт строго на процессоре: `LLM_N_GPU_LAYERS = 0`. Число потоков
берётся как половина логических ядер, чтобы генерация не подвешивала
интерфейс.

## Установка `llama-cpp-python`

Пакет вынесен в отдельный файл зависимостей, потому что собирается из
исходников и требует компилятор. Готовое колесо ставится без сборки:

```powershell
pip install llama-cpp-python --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
```

Если пакет не установлен, приложение запускается и работает на резервных
фразах — в шапке отображается «модель не найдена».

### Ошибка «Wheel is invalid»

```
Downloading llama_cpp_python-…-win_amd64.whl
     - 0 bytes ? 0:00:00
ERROR: Wheel 'llama-cpp-python' … is invalid.
```

Файл скачался нулевого размера: загрузка оборвалась, а pip успел сохранить
пустышку в кэш и предлагает её при каждой следующей попытке. Повторный запуск
той же команды поэтому ничего не меняет.

Порядок действий:

```powershell
pip cache remove llama_cpp_python
pip install llama-cpp-python --no-cache-dir --timeout 120 --retries 10 ^
    --extra-index-url https://abetlen.github.io/llama-cpp-python/whl/cpu
```

Если обрыв повторяется, файл скачивается отдельно — браузером или менеджером
загрузок, который умеет докачивать, — со страницы
<https://abetlen.github.io/llama-cpp-python/whl/cpu/llama-cpp-python/>
и устанавливается из файла:

```powershell
pip install C:\путь\к\llama_cpp_python-0.3.34-py3-none-win_amd64.whl
```

Перед установкой стоит убедиться, что размер файла отличен от нуля и
составляет несколько десятков мегабайт.

## Где в коде

| Файл | Назначение |
|---|---|
| `app/ai_module.py` | загрузка модели, генерация, резервные фразы |
| `app/prompt_formats.py` | шаблоны разметки диалога и автоопределение |
| `app/oracle_safety.py` | проверка запросов до обращения к модели |
| `app/config.py` | путь к файлу, температура, число потоков, формат |

Модель используется в четырёх местах: мотивационная фраза при создании
квеста, разбиение квеста на подшаги, напоминание о дедлайне и диалог с
Оракулом. Каждое обращение проходит через общую функцию `_generate`,
которая гарантированно не выбрасывает исключений: любая ошибка инференса
логируется и подменяется резервной фразой.
