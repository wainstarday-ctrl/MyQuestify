### На что обратить внимание

**pystray под LGPL-3.0.** Это единственная зависимость с копилефтом.
LGPL допускает использование в проприетарном продукте при условии, что
пользователь может заменить саму библиотеку на изменённую версию. При
сборке в один файл через PyInstaller библиотека упаковывается внутрь, что
затрудняет замену. Практические варианты:

* публиковать проект с исходным кодом (для дипломной работы это обычная
  практика) — тогда требование выполняется само;
* собирать с флагом `-OneDir`, где библиотека лежит отдельным файлом;
* собирать с `-NoTray`, если значок в трее не нужен (напоминания при этом
  перестают приходить при закрытом окне).

**PyInstaller под GPL.** У проекта есть явное исключение: программы,
собранные с его помощью, не обязаны наследовать GPL. Сам bootloader при
этом остаётся под GPL — если вы его модифицируете, изменения нужно
опубликовать. В проекте bootloader не модифицируется.

**Matter.js вендорится вручную.** Файл `static/js/vendor/matter.min.js`
не входит в поставку и скачивается пользователем. При публикации проекта
файл нужно закоммитить вместе с текстом лицензии MIT — она требует
сохранять уведомление об авторских правах.

## Языковая модель

Модель **не входит** в поставку: пользователь скачивает её самостоятельно.
Приложение лишь читает файл `.gguf` с диска.

| | |
|---|---|
| Модель проекта | Vikhr-Qwen-2.5-1.5B-Instruct (Q4_K_M) |
| Источник | <https://huggingface.co/Vikhrmodels/Vikhr-Qwen-2.5-1.5B-Instruct-GGUF> |
| Базовая модель | Qwen2.5-1.5B-Instruct |

Условия использования смотрите на странице модели: у моделей на Hugging
Face лицензия указывается в карточке и может отличаться от лицензии
базовой модели. Отдельно проверьте, разрешает ли лицензия коммерческое
использование, если планируете его.

Приложение спроектировано так, чтобы модель была заменяемой: формат
промпта определяется автоматически, ничто в коде не привязано к конкретным
весам. Если условия использования модели не подойдут, её можно поменять,
не трогая код (см. `docs/MODEL.md`).

## Обработка данных пользователя

Проект спроектирован так, что персональные данные не покидают устройство:

* всё хранится в локальном файле SQLite (`myquestify.db`);
* сетевых обращений нет ни при генерации, ни при работе интерфейса —
  запрещены политикой CSP в `templates/index.html` и отсутствием сетевого
  кода в приложении;
* сервер слушает только `127.0.0.1` и недоступен из локальной сети;
* аккаунтов, регистрации и телеметрии нет;
* загруженные фоны сохраняются в каталоге пользователя, оригинальное имя
  файла не используется — путь строится из UUID.

Что хранится в базе: тексты квестов, цепочки мыслей, переписка с Оракулом,
настройки, баланс токенов. Переписку пользователь может удалить кнопкой
«Очистить беседу», всю базу — удалением каталога данных.

Если проект будет распространяться публично, стоит добавить в интерфейс
краткое уведомление о том, какие данные сохраняются локально, — сейчас об
этом сказано только в условиях использования Оракула.

## Содержание, генерируемое моделью

Ответы модели непредсказуемы по своей природе. В проекте предусмотрены три
уровня защиты:

1. **Фильтр до генерации** (`app/oracle_safety.py`) — детерминированный код,
   который нельзя обойти уговорами, в отличие от системного промпта.
2. **Фильтр после генерации** — тот же код проверяет уже готовый ответ,
   потому что модель может свернуть в опасную тему сама.
3. **Правовая оговорка** — под чатом и в отдельном окне условий.

Оговорка прямо указывает, что ответы не являются профессиональной
консультацией и что взаимодействие не создаёт отношений «врач — пациент»
или «адвокат — доверитель». Полный текст — в окне «Подробнее» рядом с
полем ввода.
